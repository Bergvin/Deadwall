# DW Classic (frozen original mode)

This is the project guide as it stood when DW Classic was frozen (Oct 2026). The code lives in `src-classic/` (page `classic.html`), its tests in `tests/classic/`, its balance script in `tools/simulate-classic.js`. Every path below that says `src/` means `src-classic/` now. Classic keeps its own save key (`deadwall.save`). Change it only if the user asks for a Classic fix.

### Design decisions (approved by the user)

These fill gaps the spec leaves open:

- **Heroes can fall:** at 0 HP a hero is "fallen" (not deleted). They can be revived for gold during the next prep phase. Warn when a hero's HP is low.
- **Building during waves is allowed:** construction and repair cost **+25%** while a wave is active.
- **Starting layout:** only the castle and the gate. The player builds every defensive line.
- **Map:** fixed, about **30×24** cells, fits on screen with light zoom.
- **No victory condition:** endless waves, the goal is a personal best. Milestone markers at waves 10, 20, 30, …
- **Repositioning takes time:** the hero walks to the new spot for a few seconds and does not attack meanwhile.
- **Hero names:** random medieval names, e.g. "Aldric the Archer".
- **Towers + one hero (redesign, approved):** the main firepower is elemental towers (fire/earth/wind/water, plus the **Rolling Stone Tower** that rolls a ball down a line and scatters what it hits) built on top of walls, one per wall, levels 1–3 bought with gold. One hero per run, 2× size (`CHAMPION` in config/towers.js), standing on a **2×2 block of walls**.
- **Hero build (Oct 2026 rework, approved, "make it crazy, balance second"):** no classes. The player picks a **starting weapon** (bow, crossbow, staff, flasks, sword, mace = the old class configs, now weapon *styles*); the weapon decides how the hero attacks and looks. The hero starts with **no abilities**; **every level gives a pick of 3 random abilities** (rarity per card, synergy-weighted), **chosen between waves** (picks pile up during a wave). ~50 abilities: stats, elements (fire/poison/frost/lightning) with synergies that require a tag (Wildfire, Inferno, Shatter, Deep Freeze, Plague Bloom, Thunderlord...), projectile mechanics (pierce, twin shot, **bounce**, **split**, fractal shards, storm of steel), melee mechanics (cleave, **long reach**, **whirlwind**, earthshaker), the old class actives (Fireball, Multishot, Shield Bash...) plus new physics actives (Shockwave, Hurricane), and broken-on-purpose mythicals. **Weapons and gear drop during the run** (mostly elites and bosses) into a bag and are equipped between waves; legendary+ weapons grant an ability. Some imbalance is welcome: finding an overpowered combo is part of the fun.
- **Physics:** hits can knock zombies back, blasts fling them outward, whirlwinds/hurricanes throw them into the air away from the gate; flying zombies sail over walls and take fall damage; zombies collide and never fully overlap. Repeated shoves weaken (resistance stacks), and stragglers alive 40 s after a wave's last spawn become **enraged** (faster, immune to knockback) so juggling can never stall a wave.
- **Rarities:** six tiers everywhere (common, uncommon, rare, **epic**, legendary, mythical), in `config/rarities.js`.
- **Wave variants:** besides normal waves there are **Swarm** waves (many fast, frail walkers/runners, poured in quickly, half gold each) and **Chubby** waves (few brutes/siege/plague with much more HP, slow spawning, more gold each). Waves 1-2 and boss waves are always normal; a special never repeats back to back; the HUD preview names the next wave's variant.
- **Hero pacing:** max level 100, about 2 levels per wave. XP is each kill's XP shared by damage (no XP per point of damage, so a strong build cannot snowball its own levels) plus a share of a level per cleared wave.
- **Difficulty:** a commander **without upgrades should usually fall around wave 5** (a lucky build may run much further, which is fine); commander levels, skills and artifacts are what carry runs further. Enemy HP grows **exponentially** late (`WAVE_TABLE.hpGrowthExp`) because the hero build stacks multiplicatively. Last simulation (6 runs each, mixed strategy): fresh avg ≈ 10 (mostly 4-5, one 31), mid ≈ 30, strong 42+.
- **Commander (meta progression between runs):** the player is the Commander. Every finished run gives commander XP (abandoned runs give none). Each commander level offers a choice of **3 random options**, each rolled with its own rarity (common, uncommon, rare, legendary, mythical): stat perks or **skills** (automatic abilities, uncommon+). Higher rarity = stronger; taking the same again stacks. No upgrade tree. Bonuses are deliberately big.
- **Artifacts:** after every finished run the player **chooses 1 of 3 artifacts**; the further the run got, the better the rarity odds (short runs give mostly commons). Common artifacts only give a small stat bonus; **uncommon and better also give an automatic ability**. Two identical artifacts (same kind and rarity) **merge** into a higher level (max 5). Limited slots (2, +1 at commander level 4, 8, 14, 20); salvage unwanted ones for XP. **Auto-salvage** (commander setting `autoSalvage: {on, keep: [rarity]}`, toggled in the Stash header): chosen artifacts of a rarity not kept are salvaged for XP at once; a two-click button clears unkept ones already in the stash (equipped ones are never touched). No artifacts drop during a run (the earlier Wanderer creatures were removed).

### Code layout

- `src/config/`: `game.js` (MAP, ECONOMY, FORTRESS incl. gate reinforce/repair, WAVES timing, SCORE, WALLS (stone/reinforced/spiked/arcane), WALL_UPGRADES, PATHING, CAMERA; re-exports hero and enemy config), `enemies.js` (ZOMBIES: walker, runner, brute, plague, siege + bosses behemoth/gravelord with behaviour blocks; ELITE; WAVE_TABLE composition, boss every 5 waves alternating), `heroes.js` (6 classes: base stats, per-level growth, abilities, 3 talent tiers at levels 3/5/7 with two exclusive options each; HERO_RULES incl. xpToNext and maxLevel 10; TARGETING modes) and `assets.js` (model registry; hero entries carry `anims` role→clip maps).
- `src/core/simulation.js`: **one run of the whole game logic** (no rendering). Owns grid, economy, walls, fortress, zombies, heroes, projectiles, waves, seeded rng, stats; `step(dt)`, `run(seconds)`, `summary()`. Same seed + same actions = same outcome.
- `src/core/`: pure logic with no Three.js, tested in Node. `zombies.js` (flow fields per routing profile: default / siege (cheap walls → bulldozes) / charge (cost by wall HP → weakest wall); MOVE / ATTACK_WALL / ATTACK_GATE / DEAD; `damage()` kills exactly once; elites; boss summon/empower/smash-splash; zombies that end up in rocks/walls escape to the best neighbour; summons spawn on open cells), `heroes.js` (roster: recruit, deploy with capacity, reposition delay, dismiss refund, XP/levels, talents, targeting preference), `heroStats.js` (pure: stats from class + level + talents; used for live stats and "next level" previews), `combat.js` (basic attacks per class, all abilities via `use(heroId, id, target)`/`canUse`, `applyPayload` = the one place impacts become damage/DoT/slow/stun/zones, wall damage multiplier from warrior guard, paladin aura and Rally/Holy Shield buffs, paladin wall mending), `zones.js` (ground DoT areas), `wallEffects.js` (spiked thorns, arcane slow aura + pulse), `hazards.js` (plague aura + toxic puddles that damage heroes), heroes can fall at 0 HP (unseated, revive for gold only during PREP; all heroes heal on wave clear; paladin aura heals heroes), damage types physical/magic/holy/poison/fire with zombie armor/resist, `projectiles.js` (homing / point / line flight; reports impacts to combat), `waves.js` (PREP countdown / ACTIVE spawning, `startNext()` in PREP starts a wave, during ACTIVE calls the next one early: it spawns at once in its own parallel stream (`waves.called`) with its own hp/bounty, all called waves clear together and each emits `waveCleared` with its bonus; `creditedWave` (used by `summary().wave` for records and artifact odds) only counts called waves once cleared), `fortress.js` (gate HP, `gateDestroyed`), `save.js` (validated localStorage records), `rng.js`. `grid.js` (terrain, cell→wall id), `walls.js` (WallSystem: build/sell/destroy/upgrade/repair, armor, `wallStats()`, connection masks, `zombieCostFn`), `economy.js`, `pathfinding.js` (A* `findPath` + Dijkstra `computeFlowField`, 8-dir, no corner cutting), `loop.js` (fixed-timestep loop, speed/pause), `events.js`.
- `src/render/`: `setup.js` (renderer/lights/ground), `cameraController.js`, `assets.js` (AssetLibrary), `wallView.js` (`pieceFor(mask)` picks the piece and rotation), `worldView.js` (castle + scenery), `overlay.js` (grid, hover, ghost, path line), `bakedHorde.js`.
- `src/input/interaction.js`: modes (select/build), picking, wall placement (press = start, drag = axis-locked line preview with cumulative gold check, release = build; `axisLock` + 4-connected `lineCells`), right-drag pan, keys.
- `src/ui/hud.js` + `hud.css`: HTML HUD. Canvas-only pointerdown listeners keep UI clicks off the battlefield.
- `src/game/game.js`: state machine (menu → playing → over) and everything that persists between runs (renderer, camera, assets, scenery, overlay, ZombieView, ProjectileView, Effects, HealthBars, FloatingText). `src/game/session.js`: one run = Simulation + WallView + HeroView + Interaction + Hud + event→feedback wiring; `dispose()` removes every trace (restart is a new Session).
- Render: `zombieView.js` (baked horde per model; clips Walk/Punch/Death), `heroView.js` (skinned heroes on walkway y 1.18, attack/cast one-shots, invisible pick hit boxes), `fx.js` (expanding rings, zone discs, buffed-wall glow), zombie status tints via per-instance colour in the baked horde, `projectileView.js`, `effects.js` (particle bursts), `healthBars.js` (instanced camera-facing bars). `ui/screens.js` (menu, game over, pause badge), `ui/floatingText.js` (pooled DOM damage numbers).
- `src/audio/sfx.js`: procedural WebAudio sounds (no files), per-sound throttles, ambient wind; context starts on the first real pointer/key gesture. Event→sound mapping lives in `Session.#wireSound()`.
- `src/render/ambience.js` (procedural ground CanvasTexture with road to the gate, flickering torch lights, embers, drifting fog wisps, spawn glow), `breachView.js` (rubble + pulsing red ring on breached cells). Walls below 50% HP show rubble; an endangered gate smokes. The crossbowman's dagger is swapped for a small crossbow on the dagger's parent bone (GLTFLoader strips dots from names: `Weapon.R` → `WeaponR`).
- Towers: `config/towers.js` (TOWERS fire/earth/wind/water with roles, TOWER_RULES: levels, upgrade cost, price growth +5% per tower standing, 50% sell refund, ids from 100000; CHAMPION multipliers), `core/towers.js` (TowerSystem: canBuild/build (rejects no_wall/has_tower/hero_there/insufficient_gold), upgrade, sell, targeting, homing projectiles with the CombatSystem payload; a destroyed wall removes its tower, a sold wall sells it), `render/towerView.js` (Kenney hexagon tower on the walkway + element orb, one ring per level). Champion: `HeroSystem.blocksAt/canDeploy/deploy` use 2×2 blocks (`h.wallIds`, `h.block`; `positionOf` = block centre); `recruitChampion(type)` at session start, `maxHeroes: 1`. Keys `5`–`9` build towers (`9` = Rolling Stone); U/Del act on a selected tower.
- `src/ui/roster.js`: defender list on the left (champion + towers) (part of the Hud): rows with class, level, health and last-wave DPS; click selects + highlights, double-click focuses the camera; sort by DPS/Level/Class; weapon icon, ★ = ability picks waiting. Per-hero `waveDamage`/`lastWaveDps`/`totalDamage` are tracked in `Simulation` (reset on waveStarted, DPS computed on waveCleared).
- Heroes auto-cast abilities (`CombatSystem.#autoCast`, every 0.5 s): area abilities wait for a pack/boss/elite but fire on any target after 3 s ready (never hoarded); AP bolt → toughest enemy; Rally → walls under attack; Holy Shield → most hurt attacked wall. Per-hero `autoCast` toggle in the hero panel; manual Q/E/F still works. Ability names float above the caster.
- Settings (volume, muted, shadows, showPath) live in `save.settings`, edited from the main menu and the pause panel (Space), applied by `Game.applySettings()`.
- Commander: `src/config/commander.js` (RARITIES, COMMANDER xp/slots/offer weights/merge rules, ARTIFACT_ODDS (run-end rarity weights by wave reached), ABILITIES (automatic abilities: interval, target pack/several/toughest/all/walls/gate, damage per power), ABILITY_HP_SCALING, ABILITY_POWER by rarity, PERKS (stat perks with `bonus`, skills with `ability`), ARTIFACTS (bonuses per rarity + one ability), BONUS_LABELS). `src/core/commander.js` (pure: runXp/addXp, rollOffer/ensureOffer/choosePerk, rollArtifactOffer/chooseArtifact, addArtifact (merges identical ones), equip/unequip/salvage, totalBonuses, totalAbilities, and `runConfig(CFG, cmd)` = `applyBonuses(CFG, bonuses, abilities)` which returns a modified **copy** of the whole config with `COMMANDER_ABILITIES`; `Game.newGame` passes it to the Session/Simulation). Damage, attack speed and range bonuses apply to towers and the champion; health, crit, cooldown and XP to the champion only. `src/core/commanderAbilities.js` (CommanderAbilitySystem: runs `COMMANDER_ABILITIES` during active waves through `combat.applyPayload` with owner 0; War Tithe pays on wave clear; emits `commanderAbility`). The commander record is part of the save (version 2, validated in `save.js`, incl. artifact levels and the pending `artifactOffer`). The run-end offer is rolled in `Game.gameOver` and saved at once. UI: `src/ui/commanderScreen.js` (artifact choice cards, level-up cards with SKILL tags, slots, stash, totals) shown by `Screens.showCommander`; the game over screen shows the artifact choice too.
- Wave variants: `WAVE_VARIANTS` in `enemies.js` (countMult per type, ensure minimum counts, hpMult, spawnIntervalMult, rewardMult). `waveComposition(n, table, elite, variant)` applies them; `rollVariant()` picks the next one, rolled when the previous wave clears so `waves.preview()` (with `.variant`) always matches what starts. `zombies.spawn(..., { rewardMult })` scales gold and XP. `waveStarted` carries `variant`.
- Hero build: `src/config/hero.js` (WEAPON_STYLES (HEROES key → weapon name, delivery projectile/melee, icon), ITEM_NAMES, ITEM_RARITY (weapon damage, affix counts, armor base, ability grant), AFFIXES (item mods per rarity, slot, delivery), LOOT (drop chances, slot weights, rarity odds by wave, boss/elite luck, bag size), ABILITY_OFFER (rarity weights, luck per level, synergy and rank-up weights), HERO_ACTIVES (active abilities: the old class abilities + shockwave/hurricane), HERO_ABILITIES (level-up pool: rarity, tags, maxRank, requires, delivery, `mods(rank)` and/or `active`), PHYSICS). `src/core/heroBuild.js` (pure: makeItem/rollItem, itemMods/itemLines, abilityMods, rollAbilityOffer, heroMods, `applyBuild(baseStats, mods, delivery)` → final stats with every mechanic, activeConfig(id, rank)). `HeroSystem` holds `h.weapon` (its `style` = `h.type`), `h.gear {armor, trinket}`, `h.bag`, `h.abilities {id: rank}`, `h.pendingPicks`, `h.offer`; `abilityOffer`/`chooseAbility`/`equipItem`/`sellItem`/`addLoot`/`grantAbility`; changes only when `buildAllowed()` (PREP). Talents are gone (`talentTiers` returns []). Champion melee bonus (reach, damage, cleave) in `CHAMPION`. `CombatSystem`: basic attack by weapon style through `#heroPayload` (on-hit effects, knock, blast, bounce, split), `#afterHit` (chain lightning, critical cascade, bounce, split, life steal), `#melee` (whirlwind toss, cleave, earthshaker), `#onKill` (gold, heal, corpse explosions with a chain cap, wildfire, plague bloom), damage bonuses per victim (`#bonusMult`: execute, shatter, giant slayer, burning), payload `knock`/`blast`/`toss`/`roll`, actives from `abilityIds(h)`/`abilityConfig(h, id)`. Loot: `Simulation` rolls drops on kills (own rng `lootRng`), event `lootDropped`.
- Physics in `zombies.js`: `push(z, dx, dz, force, lift)` (boss/elite resist, shove stacks), `#stepPhysics` (flight over walls, landing on open ground via `nearestOpen`, fall damage, sliding bounces off walls), `#separate` (spatial-hash collisions that never push into walls/the gate/the castle), `STRIKE_TOLERANCE` so jostling crowds still strike. Fields `vx, vz, vy, air, radius, burnUntil, poisonUntil, enraged`. `zombieView` draws `z.air` as height. Enrage in `waves.js` (`WAVES.enrageAfter`).
- Hero UI: `src/ui/heroUi.js` (`buildHeroPanel`: stats, mechanics tags, owned abilities (struck through when the weapon does not fit), actives with cooldowns, equipment, bag with Equip/Sell; **auto-sell bar**: `HeroSystem.autoSell {on, keep}` sells drops of unkept rarities on drop (`addLoot` → `autoSold`), `sellUnkept` clears the bag, saved as `settings.lootAutoSell`; `AbilityPicker`: 3-card overlay that holds game time via `actions.holdTime`; `HeroNotice`: "★ N new abilities" button). `Screens.showHeroSelect` is the starting-weapon screen. `HeroView` rebuilds the model on `heroWeaponChanged`.
- `src/main.js`: bootstrap + `window.debug`.
- Grid coords: cell (x, y), y grows south, north = y 0. Cell center in world = (x + 0.5, 0, y + 0.5). Castle wall row 21, gate (15, 21), spawn rows 0–2.
- Zombie routing: walls are passable at a cost (`PATHING`), so zombies go around short walls but break through a closed line at its cheapest point.

### Commands

- `npm run dev` starts the Vite dev server on http://localhost:5173 (the in-app browser preview config is in `.claude/launch.json`, name `deadwall`).
- `npm run build` writes the production build to `dist/`.
- `npm test` runs the Node tests in `tests/*.test.js` (logic only, no browser).
- `node tools/inspect-model.cjs <file.gltf|glb>…` prints meshes, skins, textures and animation names without dumping binary data.
- `tools/patch.cjs <file>` reads `[[old, new], ...]` JSON on stdin and replaces each exactly once (fails loudly if missing). Use it via Python (`subprocess` + `json.dumps`) for multi-line edits; avoid `node -e` with template literals in Bash (backticks get eaten). `sed -i` replaces files in a way Vite's watcher on Windows can miss; if the dev server serves stale code, restart it.
- CSS class names for floaters must not collide with UI classes (e.g. `.ability` styles the ability buttons).
- `node tools/simulate.js [runs] [none|walls|fire|earth|wind|water|mixed|all] [maxMinutes]` plays headless runs with scripted strategies (champion block + rings of walls around the gate, towers, upgrades, talents, repairs) and prints the wave reached. `COMMANDER=fresh|mid|strong` plays with a commander profile (defined in the script). Targets: fresh mixed ≈ 4-5 (walls ≈ 3, fire ≈ 5), mid ≈ 11-12, strong ≈ 40. `LEVELS=1` also prints the hero's level after every wave (target: about 2 per wave). `BUILDS=1` prints each run's final weapon and abilities and which abilities show up in above-average runs (spot overpowered combos). The script hero takes the highest-rarity pick (synergy first) and wears higher-rarity drops. Re-run after any balance change and update docs/acceptance.md.
- In the browser console: `debug.state()`, `debug.newGame(seed)`, `debug.sim()`, `debug.build(x, y)`, `debug.buildLine(x0, y0, x1, y1)`, `debug.sellAt(x, y)`, `debug.addGold(n)`, `debug.spawn(type, x, y, n)`, `debug.hero(type, x, y)` (recruit + deploy; note `grid.wallAt` returns a wall id), `debug.damageWall(x, y, n)`, `debug.damageGate(n)`, `debug.fastForward(seconds)`, `debug.screenOf(x, y, h)` (cell → client pixel, for simulated clicks), `debug.cellAt(cx, cy)`, `debug.commander()`, `debug.commanderXp(n)`, `debug.giveArtifact(id, rarity)`, `debug.artifactOffer(wave)`, `debug.loot(slot, rarity, style)`, `debug.grant(abilityId, rank)`, `debug.heroXp(n)`. Note: the menu is shown first; start a run before using run commands.
- `/tools/viewer/pieces.html?m=wall,wall-corner` shows Kenney pieces top-down at 0/90/180/270° (north up) to check orientation.
- Controls: `B`/`1`–`4` build stone/reinforced/spiked/arcane wall, `U` upgrade selected wall, click the gate to repair/reinforce it, LMB place/select (drag previews a straight line, release builds it), RMB cancel, RMB-drag or WASD pan, wheel zoom (anchored at the cursor), `R` repair / Del sell selected wall, `M` move selected hero, Space pause, Enter start next wave, Esc cancel, `P` toggle the zombie path preview. Towers tab or `5`–`9` → click a free wall. Hero: `M` then click a 2×2 block of walls; ability picks and equipment in the hero panel between waves. Selected hero: `Q`/`E`/`F` abilities (targeted ones show a reach ring + area preview, click to cast).
- `.github/workflows/deploy.yml`: on every push to `main` runs `npm ci`, `npm test`, `npm run build` and publishes `dist/` to GitHub Pages. Vite `base: './'` and relative model URLs (`models/...` in config/assets.js) keep the build working under the /Deadwall/ sub-path. Never use absolute `/models/` URLs.
